# 博物馆预约时段采集服务

这是一个用于博物馆预约时段的本地数据采集与归档服务。当前版本从仓库自带的合成来源记录读取一页**三渠道**数据（官方馆方状态、旅行社代理容量、人工确认），规整后写入分轨存储，并归并为逐条可辨的行程单。整个流程在不访问外部系统的情况下即可复现。

## 三类信息为什么要分轨

同一个时段可能同时存在三种相互矛盾的说法：

- **官方状态（official）**：馆方官网因场地维护显示关闭——对“开/关”有最终决定权；
- **代理容量（agency）**：旅行社页面尚未同步，仍显示可订与余位——只代表代理自有库存，不能让官方关闭时段重新开放；
- **人工确认（manual）**：接待员电话确认保留的团体名额，带过期时间——有效时是保留行程的凭据，过期后必须重新安排。

服务不做“谁更新就听谁的”式字段合并，而是：

1. 存储层以 `slotId:channel` 为键分轨保存，任何渠道都不会因更新时间或修订号较新而覆盖另一渠道；同渠道内仅在修订号严格增大时更新；
2. 行程单条目内 `officialStatus`、`capacity`、`manualConfirmation` 三段独立可辨，各自附带来源、修订号与观察时间；
3. 官方关闭而代理仍可订时产生 `channel_conflict` 冲突与告警，建议以官方为准；
4. 人工确认按 `expiresAt` 判定：`valid` / `expiring_soon`（默认 24 小时内，提示级）/ `expired`（告警级，动作转为 `reschedule` 重新安排）；
5. 缺少官方状态时，代理可订与人工确认都不能替代开放结论，动作为 `verify_official`。

## 行程单动作

| action | 含义 |
| --- | --- |
| `hold_with_confirmation` | 官方关闭但持有有效人工确认，凭确认保留行程 |
| `reschedule` | 无有效确认的关闭时段，或人工确认已过期，重新安排 |
| `bookable` | 官方开放且代理有余位，可预订 |
| `full` | 官方开放但代理无余位，候补或改期 |
| `verify_official` | 缺少官方状态，先向馆方核实 |
| `no_data` | 三类来源均无记录 |

## 运行

需要 Node.js 20 或更高版本，不需要安装第三方依赖。

```sh
npm test
npm run build
node src/pipeline.mjs   # 输出结构化行程单 JSON 与中文可读文本
```

测试使用项目内的合成记录；执行不需要网络、凭据或外部服务。`buildItinerary(records, { now, expiryWarningMs })` 支持注入当前时间与临期阈值，便于复现过期/临期场景。
